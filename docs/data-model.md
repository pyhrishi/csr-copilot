# Data Model and the Slot Pipeline

All seed data lives in `data/seed/` and is generated by `scripts/generate-seed.py`. Validate it with `node scripts/validate-seed.mjs`. Load it **server-side** in `src/lib/data/` and pass typed objects down. Components never import JSON directly.

## Core types (implement in `src/lib/types.ts`)

```ts
export type ArmId = "velo" | "pbo";

export interface Study {
  id: string; shortName: string; title: string; sponsor: string; phase: string;
  indication: string; design: string;
  arms: { id: ArmId; label: string; randomized: number; safetyN: number }[];
  milestones: Record<"lastPatientLastVisit" | "databaseLock" | "toplineResults" | "csrTargetFinal", string>;
  template: string; therapeuticAreaPack: string; status: string;
}

export type FactKind = "n_pct" | "mean_sd" | "hr_ci" | "p_value" | "ref" | "stat";

export interface Fact {
  id: string;            // "<tlf>.<row>.<arm>", e.g. "14.3.1.1.any_teae.velo"
  tlf: string; tlfVersion: number;
  row: string; rowLabel: string;
  column: ArmId; columnLabel: string;
  population: "Randomized" | "Safety";
  kind: FactKind;
  value: { n: number; N: number; pct: number } | Record<string, number | string>;
  display: string;       // canonical rendering, e.g. "201 (67.4%)"
  cell: { row: number; col: number }; // coordinates in the TLF table
}

export interface Tlf {
  id: string; title: string; population: string; version: number;
  columns: string[];
  rows: { key: string; label: string; cells: { factId: string; display: string }[] }[];
  footnotes?: string[];
}

export interface TemplateSentence { id: string; text: string; cites: string[]; seededIssue?: string }

export interface Section {
  id: string; title: string;
  release: "R1" | "R2" | "human";
  autonomy: "L0" | "L1" | "L2" | "L3" | "locked";
  tlfs: string[];
  sentences: TemplateSentence[];
}

export interface Patient {
  id: string; arm: ArmId; armLabel: string; age: number; sex: "M" | "F"; site: string;
  event: string; seriousness: "Hospitalization" | "Death"; severity: string;
  onsetDay: number; resolvedDay: number | null; outcome: string; related: string; action: string;
  timeline: [day: number, text: string][];
  narrativeType: "SAE" | "Death"; status: "ready" | "exception"; dataIssue?: string;
}

// Runtime state (client store, persisted to localStorage per browser for the demo)
export type Provenance = "ai" | "ai_edited" | "human";
export type SentenceState = "pending" | "accepted" | "rejected";

export interface DraftSentence {
  id: string; sectionId: string;
  template: string;      // text with slots, exactly as generated
  rendered: RenderedPart[]; // output of the slot filler
  provenance: Provenance; state: SentenceState;
  cites: string[];
  generation: { mode: "simulated" | "live"; model?: string; promptVersion: string; templateVersion: string; at: string };
  findings: Finding[];
}

export type RenderedPart =
  | { type: "text"; value: string }
  | { type: "slot"; factId: string; format: SlotFormat; value: string }
  | { type: "patient"; field: string; value: string; source: PatientSource }; // {P:...} slots (narratives)
export type SlotFormat = "n_pct" | "n" | "pct" | "display";
// What a patient part cites: a field of the patient record, or one timeline entry (by index).
export type PatientSource = { kind: "field"; field: keyof Patient } | { kind: "timeline"; index: number };

// span: [start, end) character offsets in the sentence TEMPLATE. suggestion: human-readable advice.
// fix: an optional machine-applicable edit to the template (replace span with replacement).
export interface Finding {
  ruleId: string; severity: "critical" | "major" | "minor"; message: string;
  span?: [number, number]; suggestion?: string;
  fix?: { span: [number, number]; replacement: string };
}

export interface AuditEvent {
  id: string; at: string; actor: string; role: Role;
  action: "generate" | "accept" | "edit" | "reject" | "regenerate" | "sign_off" | "autonomy_change" | "tlf_update" | "export";
  objectId: string; detail: string;
  versions?: { model?: string; prompt?: string; template?: string; tlf?: string };
}
export type Role = "writer" | "biostat" | "regulatory" | "qa" | "exec";
```

## Slot syntax

| Slot | Meaning | Renders |
|---|---|---|
| `{F:<factId>}` | TLF fact, default format | `fact.display`, e.g. `201 (67.4%)` |
| `{F:<factId>\|n}` | Count only | `201` |
| `{F:<factId>\|pct}` | Percent only | `67.4%` |
| `{P:<field>}` | Patient field (narratives only) | Derived from the patient record, e.g. `{P:age}` → `71` |

Regex: `/\{F:([^}|]+)(?:\|(n|pct|n_pct))?\}/g` and `/\{P:([a-zA-Z]+)\}/g`.

Derived patient fields for the narrative template: `sexWord` (man/woman), `eventLower`, `seriousnessLower` ("hospitalization", "death"), `severityLower`, `actionLower`, `outcomeLower`, `relatedLower`, `resolvedClause` (", resolving on Day N" or ""), `timelineSummary` (the timeline joined into prose, with "Day N" prefixes generated by code).

A `{P:...}` slot renders as one or more `patient` parts, each citing its source. Two fields expand into several parts, and the text parts that code writes between them never contain a digit:
- `resolvedClause` → text ", resolving on Day " + patient part (source `resolvedDay`). It renders nothing when `resolvedDay` is null or the patient died.
- `timelineSummary` → for every timeline entry after "First dose of study drug": text "On Day " + patient part (the day) + text ", " + patient part (the entry text, quoted verbatim with only its first letter lowercased, unless the first word is an all-caps abbreviation such as "BP") + text ". ". Both patient parts cite `{ kind: "timeline", index }`.

## The pipeline (`src/lib/slots`, `src/lib/validate`, `src/lib/generation`)

1. **Plan:** choose the section's facts (from `section.tlfs`) and template sentences.
2. **Generate:** produce prose containing only slots.
   - Simulated mode streams `section.sentences[*].text`.
   - Live mode sends Claude the fact *ids and labels, never values*, with the instruction to use slots, and gets back placeholder prose.
3. **Fill:** `renderSlots(template, facts) → RenderedPart[]`. Unknown fact id → throw; never render a guess.
4. **Validate:**
   - **NUM-001:** any numeral in a `text` part (outside slots, outside "Table/Section/Listing/Figure x.y" references and rule ids) is critical. Counts written as words ("one", "twelve", "twice", "half" …) count as numerals too.
   - **STAT-001..003** come from `rules.json`.
   - **CITE-001:** every slot's fact id must appear in `cites`.
5. **Reconcile:** for each slot part, re-read the fact from the store and compare `value` to the source TLF cell display → Matched or Mismatch.
6. **Log:** append AuditEvents for generate and fill, with versions.

## Required unit tests (`src/lib/**/*.test.ts`, Vitest)

- `renderSlots` renders every format; throws on an unknown id; never emits a numeral outside slot parts.
- NUM-001 flags `"in 201 patients"` typed by a human; passes `"(Table 14.3.1.1)"`.
- STAT-001 flags seeded sentence 12.2-s3; the suggested fix removes it.
- The reconciliation of 12.2 returns 12/12 Matched; after applying TLF v2, sentence 12.2-s4 changes and still reconciles.
- Narrative assembly for CRD301-1042 contains no numerals outside slots, and its day references come from `timeline`.
- Seed validator: `node scripts/validate-seed.mjs` exits 0 (run it in CI and in the Stop hook).
